# 프론트엔드 개발 안내

React + TypeScript + Vite 기반의 프론트엔드입니다. 백엔드가 실행되지 않아도 mock 데이터로 과목 목록을 확인할 수 있습니다.

## 내 수업 화면

- `src/App.tsx`에서 기존 `initialSubjects`를 NotebookLM 형태의 둥근 카드 그리드로 표시합니다. `src/index.css`에서 밝은 배경, 파란 추가 버튼과 반응형 배치를 정의합니다. 과목 아이콘은 표시하지 않으며, 카드 높이는 데스크톱·모바일 모두 150px입니다. 내부 패딩은 세로 20px·가로 32px이고, 점 메뉴는 우측 상단에 배치합니다.
- 초기 과목과 새로 추가한 과목에는 `src/mocks/data.ts`의 `getMockDocumentsForSubject`가 `test1.pdf`~`test5.pdf` mock을 제공합니다. 카드에는 각 과목의 자료 개수만 `자료 n개` 형식으로 표시하고 과목 생성일과 최근 업로드 날짜는 표시하지 않습니다.
- 과목 카드의 점 메뉴 영역을 제외한 곳을 클릭하면 `/subjects/:id`로 이동합니다. 브라우저 뒤로 가기와 과목 페이지의 `내 수업` 버튼은 과목 목록으로 돌아갑니다. 과목 페이지는 왼쪽에 자료 목록 사이드바, 오른쪽에 선택 자료 정보를 둡니다. 사이드바 행은 파일명과 주차를 보여주며, 클릭하면 선택 상태가 강조되고 오른쪽에 파일명·주차·파일 크기·페이지 수·추가 일시가 표시됩니다. 파일 크기는 1,024바이트 기준으로 KB/MB 단위를 사용하고, 추가 일시는 현지 시간으로 표시하며 페이지 수 `null`은 `확인 전`으로 표시합니다.
- 각 과목 카드 우측 점 메뉴에는 해당 과목을 삭제하는 버튼이 있습니다. 메뉴는 한 번에 한 카드에서만 열리고, 메뉴 바깥을 클릭하면 닫힙니다. 삭제 버튼을 누르면 `src/components/ConfirmPopup.tsx` 확인 팝업이 열립니다. 확인을 눌러야 과목이 React 상태 목록에서 제거되며, 취소·닫기·팝업 바깥 클릭은 삭제하지 않고 팝업만 닫습니다. 긴 과목명은 카드에서 한 줄 말줄임으로 표시합니다.
- `수업 추가` 버튼으로 `src/components/SubjectCreateForm.tsx` 팝업을 엽니다. 팝업 바깥 클릭, 닫기 버튼 또는 취소 버튼으로 닫을 수 있고, Tab 포커스는 팝업 안에서 순환하며 닫으면 연 버튼으로 돌아갑니다. 과목 삭제 확인 팝업도 같은 포커스 제한·복귀 동작을 사용합니다. 앞뒤 공백을 제거한 과목명이 1~100자인지 검사하며, 같은 이름의 과목도 추가할 수 있습니다. 생성에 성공하면 새 과목의 `/subjects/:id` 자료 페이지로 바로 이동합니다. 과목 추가와 삭제는 React 상태에만 반영되어 새로고침 시 초기화됩니다.
- 화면 제목은 `내 수업`입니다. 버튼 모서리 반경은 기존의 절반으로, 상단 추가 버튼 12px, 폼 제출 버튼 6px, 점 메뉴 버튼 25%입니다.
- 좁은 화면에서는 과목 카드가 한 열로, 자료 목록은 화면 너비에 맞춰 배치됩니다. 과목·자료 mock은 프론트엔드 상태에서만 사용하며 백엔드 연동과 실제 PDF 열기는 포함하지 않습니다.

## 실행

Node 22 최신 패치(22.22.2 이상)와 npm을 사용합니다. nvm 사용 시 `frontend/`에서 `nvm install`과 `nvm use`로 `.nvmrc`의 버전을 선택할 수 있습니다.

```sh
cd frontend
npm ci
npm run dev
```

개발 서버는 기본적으로 `http://localhost:5173`에서 실행됩니다.

Docker에서는 저장소 루트에서 `docker compose up --build`로 실행합니다. Node와 의존성은 이미지 안에 설치되며 `src/` 변경은 HMR로 반영됩니다. Docker 환경에서는 파일 감지를 위해 1초 간격 polling을 사용하고, 로컬 실행에서는 기본적으로 사용하지 않습니다. 구성과 재빌드 기준은 [Docker 문서](DOCKER.md)를 참고합니다.

## API 주소

환경별 API 주소는 선택적으로 `frontend/.env.local`에 설정합니다. 아래 명령은 `frontend/`에서 실행합니다.

```sh
cp .env.example .env.local
```

```dotenv
VITE_API_BASE_URL=http://127.0.0.1:8000
```

공통 설정인 `frontend/src/config.ts`의 `API_BASE_URL`을 사용합니다. 환경변수가 없거나 빈 문자열이면 `http://127.0.0.1:8000`을 사용합니다. 변경 후에는 개발 서버를 재시작하고, 빌드 결과에 반영하려면 다시 빌드합니다. `.env.local`은 Git에서 제외됩니다. `VITE_` 환경변수는 클라이언트에 노출되므로 비밀 값을 넣지 않습니다.

현재 화면에서는 API 요청을 수행하지 않습니다.

Docker Compose는 루트의 선택적인 `.env` 설정을 사용합니다. `VITE_API_BASE_URL`이 미지정 또는 빈 값이면 `http://127.0.0.1:<BACKEND_PORT>`를 전달합니다. Docker 없이 실행하는 경우의 기본값 `http://127.0.0.1:8000`은 유지됩니다. `frontend/.env.local`은 Docker 이미지에 포함하지 않습니다.

## 검증

아래 명령은 `frontend/`에서 실행합니다.

```sh
npm test
npm run test:watch
npm run build
npm run lint
```

Vitest와 jsdom, React Testing Library로 테스트합니다. 검증 기준은 [테스트 문서](TESTING.md)를 참고합니다.
