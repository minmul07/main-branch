# 프론트엔드 개발 안내

React + TypeScript + Vite 기반의 프론트엔드입니다. 과목 목록과 생성에는 백엔드가 필요합니다.

PDF 원문 렌더링에는 Mozilla PDF.js의 `pdfjs-dist`와 Vite가 제공하는 worker를 사용합니다. 자료를 선택하면 `GET /documents/{id}/file`에서 PDF를 불러와 1페이지부터 세로로 표시합니다. 스크롤바, 이전·다음 아이콘 또는 페이지 번호 입력 후 Enter로 이동합니다. 빈 값, 소수, 범위 밖 번호는 현재 페이지로 복원됩니다. 확대·축소 아이콘, Ctrl+마우스 휠(일부 터치패드의 핀치 제스처 포함), 터치 화면의 두 손가락 핀치를 지원하며 배율을 25~400%로 표시합니다. 맞춤 아이콘은 너비 맞춤과 높이 맞춤을 전환하며 수동 배율에서는 너비 맞춤을 제공합니다. 너비 맞춤은 좌우 여백 없이 현재 페이지를 뷰어 너비에 맞춥니다. 맞춤 배율은 현재 페이지와 뷰어 크기에 따라 조정됩니다. 화면 주변의 페이지만 렌더링하고 로딩 실패 시 재시도할 수 있습니다. 현재 캔버스 렌더링을 사용하므로 텍스트 선택 및 검색은 지원하지 않습니다.

배율 표시를 클릭하면 백분율을 직접 입력할 수 있습니다. Enter 또는 입력란 바깥 클릭으로 적용하고 Escape로 취소합니다. 25~400 범위 밖이나 잘못된 값은 기존 배율을 유지합니다.

개별 페이지를 불러오거나 그리는 데 실패하면 한 번 자동 재시도합니다. 다시 실패하면 해당 페이지에서 직접 재시도할 수 있습니다.

뷰어의 가로·세로 스크롤바는 반투명한 회색으로 표시되며 스크롤이 멈춘 지 1초 후 사라집니다. 드래그할 수 있고 둥근 뷰어 테두리 안쪽에 배치됩니다.

## 내 수업 화면

- `GET /subjects`로 과목을 불러와 카드로 표시하며 로딩, 빈 목록, 오류와 재시도를 지원합니다. 직접 과목 주소로 진입할 때도 조회가 완료된 후 과목을 확인합니다.
- 과목 카드를 클릭하면 `/subjects/:id`로 이동합니다. 브라우저 뒤로 가기와 과목 페이지의 `내 수업` 버튼은 목록으로 돌아갑니다. 자료 선택 시 원문이 표시되고 뷰어 박스 위에 독립된 제목과 정보 아이콘이 나타납니다. 아이콘에 마우스를 올리거나 초점을 두면 파일 정보가 나타납니다.
- 자료 목록 왼쪽의 접기 버튼으로 목록을 숨기면 테두리가 왼쪽 위 위치를 유지하며 원형으로 줄어들고 아이콘도 원의 중심으로 이동하며 방향이 바뀝니다. 뷰어는 너비를 채우고 원형 펼치기 버튼을 누르면 목록 내용이 서서히 나타납니다. 키보드 초점도 해당 버튼으로 이동합니다. 축소된 동작 선호 설정에서는 애니메이션을 생략합니다.
- 과목 카드의 점 3개 메뉴에 삭제 버튼을 표시합니다. 삭제를 누르면 대상 이름과 삭제 정책을 확인하는 대화상자가 열립니다. 빈 과목은 확인 후 삭제하며, 자료가 있으면 과목명 입력 확인을 추가합니다. 성공 후 서버 목록을 다시 조회합니다. 메뉴는 한 번에 하나만 열리고 바깥을 클릭하면 닫힙니다.
- `수업 추가` 팝업에서 앞뒤 공백을 제거한 1~100자 이름을 `POST /subjects`로 전송합니다. 중복 이름을 허용하며 성공 시 서버 ID로 이동합니다. 요청 중 중복 제출과 닫기를 막고 실패 시 입력값과 오류를 유지합니다.
- 화면 제목은 `내 수업`입니다. 버튼 모서리 반경은 기존의 절반으로, 상단 추가 버튼 12px, 폼 제출 버튼 6px, 점 메뉴 버튼 25%입니다.
- 자료 페이지는 화면 높이 안에 배치하며 자료가 많으면 목록 내부에서 스크롤합니다. 좁은 화면에서는 과목 카드가 한 열로 배치되고 높이가 제한된 자료 목록 아래에 뷰어가 나타납니다.

## 실행

Node 22 최신 패치(22.22.2 이상)와 npm을 사용합니다. nvm 사용 시 `frontend/`에서 `nvm install`과 `nvm use`로 `.nvmrc`의 버전을 선택할 수 있습니다.

```sh
cd frontend
npm ci
npm run dev
```

개발 서버는 기본적으로 `http://localhost:5173`에서 실행됩니다.

Docker에서는 저장소 루트에서 `docker compose up --build`로 실행합니다. Node와 의존성은 이미지 안에 설치되며 `src/` 변경은 HMR로 반영됩니다. Docker 환경에서는 파일 감지를 위해 1초 간격 polling을 사용하고, 로컬 실행에서는 기본적으로 사용하지 않습니다. 구성과 재빌드 기준은 [Docker 문서](DOCKER.md)를 참고합니다.

## API 주소

환경별 API 주소는 선택적으로 `frontend/.env.local`에 설정합니다. 아래 명령은 `frontend/`에서 실행합니다.

```sh
cp .env.example .env.local
```

```dotenv
VITE_API_BASE_URL=http://127.0.0.1:8000
```

공통 설정인 `frontend/src/config.ts`의 `API_BASE_URL`을 사용합니다. 환경변수가 없거나 빈 문자열이면 `http://127.0.0.1:8000`을 사용합니다. 변경 후에는 개발 서버를 재시작하고, 빌드 결과에 반영하려면 다시 빌드합니다. `.env.local`은 Git에서 제외됩니다. `VITE_` 환경변수는 클라이언트에 노출되므로 비밀 값을 넣지 않습니다.

Docker Compose는 루트의 선택적인 `.env` 설정을 사용합니다. `VITE_API_BASE_URL`이 미지정 또는 빈 값이면 `http://127.0.0.1:<BACKEND_PORT>`를 전달합니다. Docker 없이 실행하는 경우의 기본값 `http://127.0.0.1:8000`은 유지됩니다. `frontend/.env.local`은 Docker 이미지에 포함하지 않습니다.

## 검증

아래 명령은 `frontend/`에서 실행합니다.

```sh
npm test
npm run test:watch
npm run build
npm run lint
```

Vitest와 jsdom, React Testing Library로 테스트합니다. 검증 기준은 [테스트 문서](TESTING.md)를 참고합니다.
- 자료 페이지는 `GET /documents?subject_id=`로 실제 목록을 조회하며 로딩, 빈 목록, 오류 재시도를 제공합니다.
- 자료 추가 팝업에서 PDF를 여러 개 선택하거나 드롭하고 파일별 양의 정수 주차를 입력합니다. 파일별 POST 결과를 표시하며 실패 항목만 재시도합니다. 모든 파일이 업로드되면 업로드 버튼 대신 파란 닫기 버튼을 표시합니다. 네트워크 실패 후 재시도는 중복 등록될 수 있습니다.

PDF.js 런타임 자산은 설치된 pdfjs-dist의 cmaps, wasm, standard_fonts, iccs에서 가져옵니다. Vite는 개발 서버에서 /pdfjs/로 제공하고 빌드 결과에도 같은 경로로 포함합니다. 뷰어는 BASE_URL을 반영한 자산 URL과 압축 CMap 옵션을 설정하여 CJK 문자와 JPEG2000 디코더 등을 로컬에서 로드합니다.

현재 페이지는 뷰포트와 세로 경계가 겹치는 페이지 중 상단이 뷰포트 상단에 가장 가까운 페이지로 결정합니다. 긴 페이지나 확대 상태에서 화면 밖의 다음 페이지로 번호가 먼저 바뀌지 않으며, 페이지 사이 여백만 보이면 기존 번호를 유지합니다.

## 과목·자료 삭제

- 팝업을 열면 자료 유무를 조회합니다. 빈 과목은 “**과목명**을 삭제하시겠습니까?”, 자료가 있으면 바로 “등록된 자료가 존재합니다. 과목을 삭제하려면 **과목명**을 입력하세요.”와 입력란을 표시합니다. 과목명은 굵게 표시하며 확인 절차는 한 단계입니다.

- 과목 카드 메뉴와 각 자료 행의 삭제 버튼에서 확인창을 엽니다. 취소·Escape·배경 클릭은 변경 없이 닫고 원래 버튼으로 초점을 돌립니다. 대상이 사라졌으면 사용 가능한 첫 컨트롤로 이동합니다. 확인창은 취소에 초기 초점을 두고 Tab 초점을 내부에 유지합니다.
- 요청 중 진행 상태를 표시하고 중복 제출·취소·배경 닫기를 막습니다. 성공 전 목록이나 선택을 제거하지 않습니다. 화면 전환으로 확인창이 해제된 뒤 도착한 응답은 이전 선택을 직접 변경하지 않고 현재 화면의 서버 목록 재확인을 알립니다. 응답 전에 같은 과목으로 복귀했더라도 재조회로 삭제된 선택과 뷰어를 정리합니다. 과목 목록 복귀 시 서버 목록을 다시 조회합니다.
- 자료 조회 중에는 삭제를 비활성화하며 조회 실패 시 재시도를 제공합니다. 빈 과목은 확인 즉시 삭제하며, 자료가 있는 과목은 과목명이 정확히 일치해야 삭제 버튼이 활성화됩니다. `confirmed_name`을 함께 보내 과목·자료·원본 PDF를 삭제합니다. 조회 후 자료가 추가되어 409가 발생하면 이름 입력으로 전환해 보호합니다. 취소하면 삭제하지 않습니다. 자료 삭제는 기존 확인 절차를 유지합니다. 상세 계약은 [API 문서](API.md)를 따릅니다.
- 성공 후 실제 목록을 재조회하고 삭제된 선택 자료의 PDF 뷰어를 해제합니다. 다른 자료의 선택은 유지합니다. 목록 재조회 실패는 삭제 완료와 구분해 안내하고 DELETE를 반복하지 않고 목록 조회만 다시 시도합니다.
- 422는 잘못된 ID를 안내합니다. 404·네트워크·서버 오류는 기존 대상을 유지하며 목록 다시 확인을 제공합니다. 특히 500도 DB 반영 후 파일 정리 실패일 수 있으므로 서버 처리 여부를 추측하지 않습니다. 목록 재확인에서 사라진 선택 자료도 해제합니다.
- `DeleteDialog.test.tsx`, `App.test.tsx`, `SubjectDocumentsPage.test.tsx`에서 확인·취소, 키보드 초점, 중복 요청, 204/404/409/422/500 및 네트워크 오류, 목록 재확인, 선택 자료 해제와 과목 전환 중 늦은 응답을 검증합니다.
### 삭제 직접 검증 기록 (2026-11-04)

- Windows, Docker Engine 29.9.2, 격리 Compose 프로젝트 `issue27-ui-check`, backend 28027/frontend 25127, 컨테이너 Node 22.23.4에서 확인했습니다. 기존 개발 DB·업로드는 사용하지 않았습니다.
- 실제 Orca 브라우저에서 PDF가 있는 과목 삭제 시 409 안내와 과목 보존, PDF 선택·렌더링 후 자료 삭제 204와 목록·뷰어 해제, 빈 과목 삭제 204, 새로고침 후 삭제 결과와 다른 과목 유지를 확인했습니다. 백엔드 재시작 뒤에도 삭제 과목·자료·원본은 404이며 다른 과목은 유지됐고 `/data/uploads`는 비어 있었습니다. 브라우저 콘솔 오류는 없었습니다.
- 로컬 Node 26.13.0에서 `npm.cmd test` 41개, `npm.cmd run build`, `npm.cmd run lint`가 통과했습니다. Docker Node 22에서도 테스트 41개·빌드·린트가 통과했습니다. Docker 테스트에는 기존 PDF 뷰어 테스트의 기본 주소 전제에 맞춰 `docker compose exec -e VITE_API_BASE_URL=http://127.0.0.1:8000 frontend npm test`를 사용했습니다. 검증 서버 자체의 API 포트는 28027을 유지했습니다.
- 실제 네트워크 단절·파일 제거 실패를 브라우저에서 주입하지 않았습니다. 해당 결과의 UI 처리는 API 모의 테스트로 검증했습니다. fresh clone 및 macOS 실행은 수행하지 않았습니다.
